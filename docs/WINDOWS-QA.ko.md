# Windows QA 체크리스트

Windows 10/11 x64 네이티브 환경에서 확인합니다. 아직 Windows 실기기에서 확인하지 않은 설치·작업 스케줄러 동작을 검증하기 위한 체크리스트입니다.

## 준비와 설치

1. Node.js 20 이상, Git, npm 전역 설치 OpenCodex를 준비합니다. OpenCodex를 실행하고 계정을 등록합니다.
2. 본인의 ngrok 고정 HTTPS 주소와 Authtoken을 준비합니다.
3. [Quick Start](QUICKSTART.ko.md)의 설치 명령을 PowerShell에서 실행합니다.
4. 토큰 입력이 화면에 노출되지 않고 `Ready:`가 출력되는지 확인합니다.
5. `npm run service:status`에서 현재 사용자의 작업이 실행되는지 확인합니다.
6. 작업 스케줄러에서 `OpenCodexMobile-사용자명`의 로그인 트리거와 실행 계정을 확인합니다.

## 휴대폰

- 본인 주소와 연결 코드로 로그인하고 **최신 조회**가 성공하는지 확인합니다.
- iPhone 또는 Android에서 홈 화면 설치 후 같은 대시보드가 열리는지 확인합니다.
- 알림 등록·테스트 후 실제 수신을 확인합니다. 서비스 접수 성공과 실제 수신을 따로 기록합니다.
- 계정 관리가 필요한 경우 일시 중지·재개 등 되돌릴 수 있는 작업만 확인합니다. QA를 위해 banked reset을 소비할 필요는 없습니다.

## 자동 시작·복구

1. 작업 관리자에서 명령줄을 확인하고 **이 앱의 웹앱 프로세스만** 종료합니다. 다른 Node 작업이나 OpenCodex는 종료하지 않습니다.
2. 약 10초 후 새 웹앱 프로세스가 실행되고 웹앱이 다시 열리는지 확인합니다.
3. 이 설치의 ngrok 프로세스만 종료하고 같은 주소로 복구되는지 확인합니다.
4. Windows 로그아웃 후 로그인합니다. OpenCodex도 실행한 뒤 웹앱·터널이 자동 시작하는지 확인합니다.
5. `npm run service:stop` 후 웹앱·터널이 종료되고 자동 시작 작업이 비활성화되는지 확인합니다.
6. `npm run setup`으로 다시 활성화하고 기존 연결 코드·로그인·알림 구독이 유지되는지 확인합니다.
7. `npm run update` 후 새 설치가 정상 실행되고 기존 데이터가 유지되는지 확인합니다.

## 실패 보고

Windows 버전, Node/OpenCodex 버전, 실패 단계, 오류 문구, 작업 스케줄러 상태를 기록합니다. 로그 위치는 `%LOCALAPPDATA%\OpenCodexMobile\.data\web.log`와 `tunnel.log`입니다. 공유 전에 민감한 값을 가리세요.

연결 코드, ngrok Authtoken, 세션·위젯 키, 계정 인증 정보 및 `.data` 폴더 전체를 이슈나 채팅에 올리지 마세요. 실제 결과를 기록하고, 실행하지 않은 단계는 미확인으로 남깁니다.
